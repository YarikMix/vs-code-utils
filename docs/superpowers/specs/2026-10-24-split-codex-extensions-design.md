# Два расширения VS Code в `vs-code-utils`

## Зачем

Вернуть `Codex Smart Paste` как самостоятельное расширение для клавиатуры и буфера обмена. Нынешнее `Codex Terminal Tool` оставить рядом в том же репозитории как самостоятельное расширение для открытия найденной истории Codex в новом терминале текущего окна VS Code. Оба должны устанавливаться одновременно в Windows Local extension host и работать с WSL-терминалами без конкуренции за сочетания клавиш.

## Согласованное поведение

- `Codex Smart Paste` владеет всей существующей логикой вставки и пятью привязками: `Ctrl+[KeyV]`, `Alt+[KeyV]`, `Ctrl+[KeyC]` при выделении, `Ctrl+Enter`, `Shift+Enter`. Он сохраняет поведение версии 0.2.0 и технический ID `local.codex-smart-paste` с командой `local.codexSmartPaste.paste`.
- `Codex Terminal Tool` владеет только каналом открытия сессий: переменными `CODEX_TERMINAL_TOOL_ENDPOINT` и `CODEX_TERMINAL_TOOL_HELPER`, проверкой UUID, оконным HTTP-мостом и созданием терминала в нижней панели текущего окна с `codex resume <UUID>`. Его технический ID остаётся `local.codex-terminal-tool`. Он не регистрирует команду вставки и не объявляет клавиатурных привязок.
- Установка или удаление одного расширения не должна отключать функцию другого. В списке **Local — Installed** они видны отдельно.
- Способ поиска UUID остаётся в существующем навыке `codex-vscode-sessions` из репозитория `agent-utils`; этот проект не меняет поиск и не решает проблему окружения общего daemon Codex. Терминальный мост сохраняет нынешний проверенный контракт, включая ограничение `--no-daemon` для агента, который вызывает helper из shell tool.

## Границы

В эту работу входят структура репозитория, отдельные сборки и VSIX, документация установки и удаления, а также проверка совместной установки. Поддержка Pi, прокси Codex, изменение Codex CLI, публикация в Marketplace и управление существующими пользовательскими `keybindings.json` сюда не входят. Выпуск GitHub Release и установка в рабочий профиль VS Code — отдельные последующие действия после готовности и проверки двух пакетов; изменение рабочего профиля не требуется для проверки в изолированном тестовом профиле.

## Структура и сборка

Репозиторий содержит два соседних каталога расширений, например `extensions/codex-smart-paste/` и `extensions/codex-terminal-tool/`. У каждого собственный `package.json`, `src`, нужные ему PowerShell-ресурсы, `.vscodeignore`, README и VSIX. Корень содержит общий README и команды разработки для сборки и тестирования обоих пакетов. Общие инструменты сборки могут находиться в корне как dev-зависимости, но итоговые VSIX должны быть независимыми: каждый содержит только свой runtime и ресурсы.

Код Smart Paste восстанавливается из проверенной версии `v0.2.0`, с сохранением поведения и IDs. Из текущего расширения удаляются импорт, активация, команда, настройки и привязки Smart Paste; код и тесты терминального моста остаются с ним. Разделение не должно оставлять две активные реализации `Ctrl+V`.

Версии следующего пакета предлагаются `codex-smart-paste` 0.3.0 и `codex-terminal-tool` 0.5.0, чтобы их было легко отличить от ранее опубликованного Smart Paste 0.2.0 и установленного Terminal Tool 0.4.0. Каждый VSIX получает имя своего пакета и версии. Общий README объясняет, что для обеих функций нужны оба расширения, и показывает отдельные команды сборки и установки. Исторические документы в `docs/superpowers/` не переписываются; в новой документации понятно указано, что старые пути относятся к прежней структуре.

## Проверка результата

1. Отдельно собрать и распаковать оба VSIX; подтвердить разные extension IDs и отсутствие чужих исходников, скриптов, команд и привязок в каждом.
2. Прогнать unit/typecheck/build для обоих пакетов. Интеграционный тест на временном профиле VS Code должен активировать оба расширения и проверить, что зарегистрирована ровно одна команда Smart Paste, а переменные оконного моста появляются от Terminal Tool.
3. На Windows 11 + WSL Ubuntu проверить в изолированном или безопасно обновлённом рабочем профиле: Smart Paste продолжает вставлять текст и изображения, `Ctrl+Enter`/`Shift+Enter` работают; helper открывает `codex resume <UUID>` в новой вкладке панели Terminal нужного окна. При двух открытых окнах одинакового workspace запрос из каждого окна должен попадать в своё окно. Если Electron-тест мешает обновлению рабочего VS Code, это отдельный риск тестового окружения, а не основание пропустить ручную проверку.
4. Проверить независимость: выключение Smart Paste не убирает переменные моста, а выключение Terminal Tool не убирает клавиатурные команды Smart Paste. Пользовательские привязки и действующие Codex-сессии во время проверки не изменяются.

## Известные зависимости и риски

- Открытый PR #6 (`docs-codex-daemon-env`) меняет документацию старого единого расширения. Перед объединением веток его содержание следует перенести в README пакета Terminal Tool либо согласовать порядок слияния, чтобы не потерять описание общего daemon. Наличие PR #6 не меняет состав этого дизайна.
- У обоих расширений `extensionKind: ["ui"]`, потому что PowerShell-скрипты и оконный VS Code API работают на Windows стороне. Установка только в WSL extension host не соответствует этому контракту.
- Если пользователь установит прежнее объединённое расширение вместе с двумя новыми пакетами, старые привязки могут конкурировать. Инструкция обновления должна предписывать обновить `local.codex-terminal-tool` до версии без привязок и удалить оставшиеся исторические `local.codex-ops`, если они установлены.

## Что оставлено исполнителю

Точная организация корневых команд Bun и переиспользование test runner, механика переноса исходников без копирования runtime и набор проверок каждого VSIX. Эти решения не должны менять границы функций, IDs, поведение клавиш или оконный контракт моста.
