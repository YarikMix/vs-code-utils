# Codex Ops: сессии в списке терминалов

## Поведение

Когда агент в WSL-терминале вызывает существующий `CODEX_OPS_HELPER` с UUID сессии, расширение создаёт новый терминал **в нижней панели Terminal того же окна VS Code**. Терминал виден в списке вкладок справа в этой панели, получает фокус и запускает `codex resume <UUID>`.

Создание редакторской вкладки терминала для новых запросов больше не требуется. Уже открытые редакторские вкладки автоматически переносить не нужно.

## Границы изменения

Сохранить текущий канал с отдельным адресом и токеном для каждого окна, строгую проверку UUID, окружение новых терминалов, профиль и рабочий каталог VS Code, а также Smart Paste и его привязки. Codex CLI и отображение статусов сессий не менять.

Использовать публичный API VS Code `TerminalLocation.Panel`, поддерживаемый минимальной версией расширения `^1.85.0`. Выпустить новый VSIX `codex-ops-0.3.1.vsix` с версией `0.3.1`, обновить инструкцию установки и проверку версии в интеграционном тесте. Историческую спецификацию версии `0.3.0` оставить как запись о прежнем решении.

## Проверка

Регрессионный unit-тест должен отличать `TerminalLocation.Panel` (`1`) от прежнего `TerminalLocation.Editor` (`2`) и проверять сохранение `codex resume <UUID>` и вызова `show()`. Затем нужны полный unit suite, typecheck, упаковка VSIX и ручная проверка в новом WSL-окне VS Code. Текущие окна с запущенными сессиями не перезагружать ради проверки.
