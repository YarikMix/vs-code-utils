# TypeScript, Bun и интеграционные тесты Codex Smart Paste

## Согласованная цель
Перевести расширение в YarikMix/vs-code-utils на TypeScript со strict-проверкой, Bun для зависимостей/скриптов/модульных тестов, esbuild для сборки и @vscode/test-electron для тестов в настоящем VS Code. Выполнить через SDD: отдельные агенты реализации, проверки задач и финальный обзор. Обновить открытый PR #1; не выполнять merge и публикацию в Marketplace.

## Контекст и выбор
В репозитории уже есть работающая реализация JS, 14 Node-тестов и VSIX 0.1.0. Пользователь согласовал перенос на TS+Bun+esbuild. Альтернативы — оставить JS или использовать реактивный фреймворк — не выбираются: изменение направлено на типизацию и проверку интеграции, а дополнительных интерфейсов/реактивного состояния нет.

## Структура и сборка
src/extension.ts — регистрация команды и адаптеры VS Code; src/smart-paste.ts — типизированный маршрутизатор; отдельный модуль проверки Windows-буфера при необходимости для ясной границы тестирования. scripts/contains-image.ps1 сохраняется. Проверка PowerShell использует путь ресурса из ExtensionContext, а не расположение исходного entrypoint: после сборки файл JS находится в dist.

TypeScript strict: true; типы vscode.Terminal/ExtensionContext и узкий интерфейс зависимостей маршрутизатора; ошибки на границах обрабатываются как unknown. В runtime нет зависимости от Bun API. esbuild собирает CommonJS dist/extension.cjs с platform node и external vscode; main в манифесте указывает на этот файл. Целевая версия JS совместима с минимальным VS Code из engines.vscode; сборка не поднимает этот минимум без причины.

Bun управляет devDependencies и зафиксированным bun.lock. Команды: bun run typecheck, bun run build, bun run test:unit, bun run test:integration, bun run package. typecheck запускает tsc --noEmit; сборка не заменяет проверку типов. bun test запускает только модульные тесты, без случайного обнаружения Electron suite. Упаковка через @vscode/vsce включает собранный runtime, README и PowerShell-ресурс, исключая исходники тестов, node_modules, lockfile и документы разработки.

## Сохранение поведения
Идентификатор local.codex-smart-paste и ID команды local.codexSmartPaste.paste сохраняются. Версия пакета 0.2.0 отличает новую сборку от установленной 0.1.0. Ctrl+[KeyV] выбирает картинку или штатную текстовую вставку; Alt+[KeyV] отправляет ESC+v; Ctrl+[KeyC] копирует только выделенный текст; Ctrl+Enter/Shift+Enter отправляют ESC[13;2u. Сохраняются terminalFocus, commandsToSkipShell, приоритет картинки, таймаут 3000 мс, запрет повторной операции и отмена при смене активного терминала. Текст/изображения буфера не логируются и не изменяются фоновыми процессами.

## Проверки
Модульные тесты Bun сохраняют все 14 проверенных сценариев, используя штатные механизмы Bun и явные интерфейсы вместо подмены CommonJS загрузчика. Добавляется проверка корректного пути PowerShell-ресурса после сборки.

Интеграционные тесты через @vscode/test-electron запускают отдельный Extension Development Host с временными user-data и extensions directories. Проверяют загрузку именно собранного entrypoint, активацию расширения, регистрацию команды, эффективное commandsToSkipShell, манифест всех привязок и передачу точных ESC-последовательностей встроенной командой sendSequence в тестовый Pseudoterminal. На Windows проверяют разрешение и запуск упакованного PowerShell-ресурса, возвращающего только boolean, без изменения пользовательского буфера. У тестового окна нет автоматических команд отправки сообщения в Telegram или Codex.

@vscode/test-electron проверяет реальный API и интеграцию, но сам не воспроизводит физические нажатия клавиш/переключение раскладки. Эта граница явно описывается в README и PR: ручная проверка обеих раскладок, текста и скриншота остается обязательной для утверждения о физических сочетаниях.

Основная интеграционная проверка Windows выполняется доступным Windows VS Code/Electron, несмотря на запуск разработки из WSL. Если среда не позволяет запустить выбранную версию Electron, зафиксировать точную причину; не выдавать отсутствие запуска за успешный тест и продолжить доступные проверки. Не устанавливать глобальные пакеты и не менять постоянные политики PowerShell.
